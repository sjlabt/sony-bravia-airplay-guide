索尼电视免费投屏：DLNA 和 AirPlay，一个接收器全搞定

国内视频 App 投屏走的是 DLNA，iPhone 和 Mac 走的是 AirPlay——两套协议，但一个开源接收器可以同时提供。这篇教程记录我们在索尼电视上的完整操作：每一步都写清「怎么做、看到什么算成功、出错怎么查」，全程不需要 root，不用花钱，也没有广告和会员。

一、先说结果

一句话版本。用电脑通过 ADB，给索尼电视装一个开源 App MiracastReceiver。装完就有两样东西：国内 App 的「投屏」能找到电视（DLNA 推送，手机可以切走，电视自己播）；iPhone、iPad、Mac 的 AirPlay 菜单里也能找到电视（屏幕镜像、投视频）。

  • 花费：0 元。开源软件，无广告、无会员、无登录。
  • 需要：电视是安卓/Google TV，且设置里有「无线调试」（一般是 Android 11 及以上）；一台电脑（Windows 或 macOS）；两者连同一个 Wi-Fi。
  • 时间：约 15 分钟。装完之后电脑就可以收起来，日常投屏不再需要它。
  • 实测环境（本文所有细节以此为准）：2026-10-12，国行索尼 BRAVIA 4K AE1（系统里的设备名是 SONY XR-65A95L），Android 14，CPU 为 32 位（armeabi-v7a）。你的机器以自己电视上读到的信息为准，方法通用。
写在前面：少数机型会遇到「DLNA 正常、但 AirPlay 列表里没有电视」的问题，我们这台就遇到了，原因和完整修复方案写在第九节。先正常往下做，真遇到再去那里，不是你的操作问题。

二、两种投屏先分清

DLNA 推送AirPlay
谁在用B 站、优酷、爱奇艺等国内 App 的「投屏」按钮；Windows 媒体播放器、VLC、Emby 等iPhone、iPad、Mac 的「屏幕镜像」和视频投屏
播在哪电视自己拉流播放。投上之后手机可以退出 App、去干别的镜像时手机画面实时传过去，手机熄屏或退出就会断
电视上要有什么一个 DLNA/UPnP 接收端（MediaRenderer）_airplay._tcp 服务广播（音频另有 _raop._tcp）

两个补充说明，避免后面误会：

  • 搜得到设备，不等于每个视频都能播。这些 App 给出的视频地址常带短时鉴权，过期或源站拒绝时，任何接收端都补不了——换个视频或换清晰度重投即可，这不是安装出了问题。
  • Netflix、Apple TV+ 等 DRM 内容镜像时会黑屏，这是内容保护机制，属于正常现象。普通桌面、照片、网页和非 DRM 视频不受影响。

三、你的电视能不能用

满足这三条就可以：

  1. 电视机型：索尼 Android TV / Google TV（近些年的 BRAVIA 基本都是）。不是安卓系统的老 BRAVIA 没有这条路。
  2. 系统版本：Android 11 及以上——判断标志是「设置」里能找到「无线调试」（在开发者选项里）。现在找不到没关系，第六节第 1 步教你打开开发者选项。
  3. 网络：电视和电脑连同一个 Wi-Fi / 局域网。一边连主路由、一边连访客网络，后面会表现为连不上。

不太确定的旧机型：如果开发者选项里只有「网络调试」、固定端口 5555、没有配对码（Android 10 及更早），本文的端口流程不适用，可以参考文末参考里的原教程。另外，安卓电视上的「广播名字」不一定等于系统型号（我们这台：AirPlay 广播名是 SONY XR-65A95L，系统读出来却是 BRAVIA 4K AE1），后面第六节第 4 步会让你核对，以连接后读到的为准。

四、开始前必须知道的三个坑

坑 1：配对端口 ≠ 连接端口。
电视的「无线调试」上有两个不同的端口：配对端口显示在「使用配对码配对设备」弹窗里，只在配对时有效；连接端口在无线调试主页面，连接用，而且会变。把配对端口拿去 adb connect、或把连接端口拿去 adb pair，都会失败，报错还看起来像网络问题。一切以电视屏幕上当时显示的为准。
坑 2：APK 分 32 位和 64 位，下错装不上。
下 APK 之前先查电视的 CPU 架构（第六节第 5 步有命令）：armeabi-v7a 是 32 位，arm64-v8a 是 64 位，要下对应的包。拿不准就下 universal 包（两种架构都在里面），多占 3 MB 而已。我们这台电视只有 32 位，64 位的包装不上。
坑 3：少数机型 AirPlay 列表里不显示电视。
表现是：DLNA 投屏正常、端口也正常，但 iPhone / Mac 的 AirPlay 菜单里找不到电视。我们实测的 BRAVIA 4K AE1 属于这一类，原因和修复方法在第九节。先照常做，做到第六节第 7 步验证时留意一下即可，不是你操作错了。

六、操作步骤

第 1 步：在电视上打开「无线调试」

  1. 确认电视和电脑连的是同一个局域网。
  2. 电视上打开「设置 → 关于」（不同系统在「设备偏好设置」或「系统」分类里），找到「版本号」，连续点击约 7 次，直到提示开发者模式已开启。
  3. 返回设置，进入「开发者选项」，打开「无线调试」。
  4. 进入无线调试页面，你会看到两个东西：主页面显示 IP 和「连接端口」；点开「使用配对码配对设备」，弹窗里显示 6 位配对码 + IP + 「配对端口」。配对弹窗先不要关。
看清楚了：这个弹窗里的端口是「配对端口」，只用于下一步的配对命令；连接用的是主页面那个「连接端口」。记不清就翻回第四节坑 1。

第 2 步：电脑装 ADB

macOS（推荐 Homebrew）：

brew install --cask android-platform-tools
adb version

没有 Homebrew 的话，到 Google 的 Platform-Tools 页面下载 macOS 版 zip，解压后在该目录里用 ./adb。

Windows：

  1. 同一下载页，选 platform-tools-latest-windows.zip，解压到一个固定目录，比如 C:\platform-tools。
  2. 在该目录里打开 PowerShell（地址栏输入 powershell 回车也行）。
  3. 运行：
cd C:\platform-tools
.\adb.exe version

✅ 怎么算成功：屏幕上打印出版本号（形如 Android Debug Bridge version 1.0.41）。

第 3 步：配对（输一次配对码）

电脑上运行（把 IP 和端口换成电视配对弹窗里显示的，下面只是例子）：

adb pair 192.168.1.30:40975

提示 Enter pairing code: 时，输入电视上那 6 位配对码（输入时屏幕上不显示字符，正常）。

✅ 怎么算成功：显示 Successfully paired。成功后配对弹窗可以关掉了。

两个注意：

  • 配对码现用现输，别写进脚本或笔记。
  • 配对是一次性的，以后再用不用重新配（除非你在电视上「忘记」了这台电脑）。

第 4 步：连上电视，核对是不是这一台

adb connect 192.168.1.30:43733

（用的是连接端口，在无线调试主页面，不是配对端口。示例数字只是格式演示，以电视上显示的为准。）

✅ 怎么算成功：显示 connected to 192.168.1.30:43733。然后核对设备：

adb -s 192.168.1.30:43733 shell getprop ro.product.model
adb -s 192.168.1.30:43733 shell getprop ro.product.cpu.abi
  • 型号：和电视对得上就继续。对不上（比如家里有不止一台安卓设备）先 adb disconnect 换正确的 IP，不要稀里糊涂往下装。
  • ABI：这就是下一步选 APK 的依据。armeabi-v7a = 32 位，arm64-v8a = 64 位。

说明：电视的「广播名字」可能和系统读出的型号不一样（我们这台广播名 SONY XR-65A95L、型号却是 BRAVIA 4K AE1），只要确认是你这台电视即可。

第 5 步：下载并安装接收器

  1. 按上一步读到的 ABI，从第五节的下载表里下载对应的 APK。
  2. （建议做）校验文件有没有下坏或被动过手脚：
# macOS
shasum -a 256 miracast-receiver-v1.2.5-armeabi-v7a.apk

# Windows
certutil -hashfile miracast-receiver-v1.2.5-armeabi-v7a.apk SHA256

输出和第五节表里的 SHA-256 一致即可。版本更新后校验值会变，届时以 Release 页面的说明为准，对不上就重下。

  1. 安装到电视：
adb -s 192.168.1.30:43733 install -r miracast-receiver-v1.2.5-armeabi-v7a.apk

✅ 怎么算成功：显示 Success。（在终端里先 cd 到你下载 APK 的目录，再把文件名替换成实际文件名；这一步和上一步的校验命令都要在「APK 所在的目录」里执行。）

  1. （可选）用命令直接把应用拉起来：
adb -s 192.168.1.30:43733 shell am start -n com.weekd.miracastreceiver/.ui.MainActivity
报 INSTALL_FAILED_UPDATE_INCOMPATIBLE？说明电视上装过签名不同的同款。先卸载再装：adb -s 地址:端口 uninstall com.weekd.miracastreceiver，然后重新 install。

第 6 步：电视上首次启动，把两个权限给它

  1. 电视上打开应用（叫 Miracast Receiver）。界面上会显示：设备名、设备 IP、「等待投屏连接...」、连接码，底部有「开机自动启动接收服务」开关——保持开启，这样以后电视重启后它自己工作，不用每次手动开。
  2. 按提示授权：
  • 「附近设备」（Android 13+）或「定位」（更早版本）：授予即可。拒绝也不影响 DLNA 和 AirPlay，但 Windows「无线显示器」类功能会不可用。
  • 「显示在其他应用上层」：这个最容易漏，务必开启。不开的后果：应用不在前台时（比如你退回电视桌面了），投屏连上也不会弹出播放画面，表现为「投屏没反应」。首次打开时应用会弹窗，点「去设置」开启；如果电视设置里没有这个选项页，用命令开：
adb -s 192.168.1.30:43733 shell appops set com.weekd.miracastreceiver SYSTEM_ALERT_WINDOW allow

第 7 步：验证两件事

A. DLNA（安卓手机投屏）：电脑上运行：

curl -fsS http://192.168.1.30:8080/device.xml

输出里应该能看到 MediaRenderer、AVTransport，以及 friendlyName（就是电视的设备名）。

然后拿手机（连同一 Wi-Fi）打开 B 站 → 视频页点「投屏」→ 列表里应能找到电视的名字 → 点它，电视开始播放。投上之后把手机切到别的 App，电视画面不受影响——如果跟着断了，说明那个按钮走的是镜像，不是 DLNA 推送。

B. AirPlay（iPhone / iPad / Mac）：Mac 上运行：

dns-sd -B _airplay._tcp local.

应能看到电视的设备名（端口 7000）。然后 iPhone：从上角滑出控制中心 →「屏幕镜像」→ 选电视名。

如果列表里还有一条名字带 (2) 的重复条目：两条一般指向同一台电视（同一端口），随便选哪条都能连。

如果 AirPlay 列表里始终没有电视（DLNA 却正常）：去第九节，那里有完整的确认方法和修复方案。

七、日常使用

  • 国内 App：B 站、优酷、爱奇艺等，点「投屏」，选电视的设备名。DLNA 是让电视自己播，手机可以退出。
  • iPhone / iPad：控制中心 →「屏幕镜像」→ 选电视名。Mac：菜单栏控制中心 →「屏幕镜像」。
  • 电视端不用每天开 App：「开机自动启动接收服务」默认开启，电视开机后服务在后台自动运行。电脑装完就可以收起来了。
  • 投屏突然「没反应」：第一个检查「显示在其他应用上层」权限还在不在（恢复出厂、换账号后可能丢掉），见第六节第 6 步。
  • 安全习惯：本方案没有账号登录，靠自家 Wi-Fi 这个内网环境隔离。不要把家里路由器上的 ADB 端口映射到公网，也不要在公共 Wi-Fi 下开无线调试。

八、常见问题速查

1）连接时报错 / macOS 提示 No route to host（错误 65）

这个报错只表示连接被拒绝，不代表一定是路由器的锅。按下面的顺序查，别跳步：

  • 先做一次对照测试（同一台电脑、同一端口）： 
    nc -G 3 -v -z 192.168.1.30 43733
  • 系统「终端」能通，但跑 adb 的那个程序不通 → 这是 macOS 的「本地网络」权限问题。打开「系统设置 → 隐私与安全性 → 本地网络」，允许你用的终端程序（Terminal / iTerm / 编辑器等）。允许后要把那个程序重启一遍，旧进程还带着旧权限。有的 App 旧版本系统不会弹窗提示，更新后再试。
  • 终端也不通，但路由器地址能通 → 查是不是访客网络、无线隔离（AP 隔离），或电视和电脑不在同一网段。
  • 连路由器都不通 → 电脑和电视根本不在同一个网络里。

不要写 TCP 转发去绕过本地网络权限；也不要把 ADB 端口映射到公网。

2）APK 装不上

  • INSTALL_FAILED_UPDATE_INCOMPATIBLE → 电视上已有签名不同的版本，先 uninstall 再装。
  • 提示解析失败 / 装不上 → 大概率是 32/64 位下错了，回去看第 4 步读到的 ABI，或者直接换 universal 包；再重新下载、重新校验 SHA-256。
  • device offline → 重新 adb connect 一次。

3）手机搜不到电视

  • 手机和电视是不是同一个 Wi-Fi？访客网络、AP 隔离都会导致搜不到。
  • 电视上应用是不是在运行（界面显示「等待投屏连接...」）？不在就先打开它。
  • 把手机 App 里的投屏页面关掉重开，再搜一次。

4）搜得到电视，但投不上 / 黑屏 / 没声音

  • 先换个视频、换个清晰度再投——个别源的地址带鉴权会失败，这是源站限制，不是接收端的问题。
  • 从 iPhone 镜像 Netflix 等内容黑屏 → DRM 保护，正常现象。
  • 投上了但电视上没画面 → 查「显示在其他应用上层」权限（第六节第 6 步）。

5）AirPlay 列表里没有电视

去第九节，有完整方案。

6）电视桌面上找不到应用图标

在电视的应用列表里翻一翻（名字叫 Miracast Receiver）；实在找不到，用第 5 步里的 am start 命令直接打开。

九、专治：AirPlay 列表里没有电视（少数机型）

先说清楚是什么情况：DLNA 一切正常、第 6 步也按要求做了，但 iPhone / Mac 的 AirPlay 列表里始终没有电视。这不是你的网络问题，也不是操作错了。我们实测的 BRAVIA 4K AE1（Android 14）就属于这一类，下面是原因和解法。

怎么确认（三个自检）

  1. Mac 上运行 dns-sd -B _airplay._tcp local. ——如果看不到电视名，但下面这条能看到，就基本坐实了： 
    dns-sd -B _miracast-receiver._tcp local.
  2. （可选）把电视重启一次，先不要打开这个应用的主界面，直接看 iPhone 的 AirPlay 列表：如果这时电视出现了，进一步印证是下面说的注册冲突（开机自启的流程不会注册那个冲突的服务）。这只是帮助确认，长期使用还是建议根治。
  3. 保持这两条的观察结果，它们也是给作者提 Issue 时最有用的信息。

是什么原因（一句话版）

应用向局域网广播两个服务：「AirPlay 服务」和它自定义的「接收服务」，但两个用了同一个名字（都是电视的设备名）。部分 Android 系统不允许同名两个服务并存，后注册的那个——恰好是 AirPlay——注册失败，所以列表里是空的。（音频服务因名字带 MAC 前缀，不冲突，所以不在这次故障里。）

Google 已在 2024 年 2 月修复了系统的这个行为（见文末 AOSP 变更，并补了兼容性测试），通过系统组件更新下发；收不到这类更新的机型（比如国行电视）仍会踩到。

修复思路很简单：给那个自定义「接收服务」换个名字（和 AirPlay 不再重名），AirPlay 就能正常注册了。这个自定义服务是应用自己私有的协议，改名不影响任何对外兼容。

方案 A：反馈给作者（推荐先做）

到项目 Issues 页提交，附上这些信息（有同款问题的用户越多，官方修复来得越快）：

  • 电视型号和系统版本（例：BRAVIA 4K AE1 / Android 14）
  • 软件版本（v1.2.5）和包（armeabi-v7a / arm64-v8a）
  • 现象：DLNA 正常、8080 端口的 device.xml 正常、7000 端口可连，但 dns-sd -B _airplay._tcp local. 看不到设备
  • 你的判断：_airplay._tcp 与 _miracast-receiver._tcp 同名注册冲突；建议给后者使用不同的实例名

如果作者后续发布了修复版，直接装新版即可，下面的重打包步骤就可以跳过。

方案 B：自己动手，改一行重新打包

需要在一台电脑上完成（Windows / macOS 都行），要装 Android Studio。如果你不熟悉这些，可以把本节内容连同整个页面发给 AI，让它带你做（见第十一节）。

  1. 装 Android Studio（官网下载，自带 JDK 和 SDK；首次打开会下载组件，网络要通畅）。
  2. 获取源码：下载或克隆项目： 
    git clone https://github.com/weekdayjast/MiracastReceiver.git
    （也可以直接在 GitHub 页面上 Code → Download ZIP，解压。）
  3. 用 Android Studio 打开项目文件夹，等它自动 Sync 完成（第一次会比较久）。
  4. 只改一行。打开文件： 
    MiracastReceiver/app/src/main/java/com/weekd/miracastreceiver/discovery/MdnsAdvertiser.kt
    找到方法 startAdvertising，把这一行： 
    this.serviceName = serviceName
    改成： 
    this.serviceName = "$serviceName MR"
    右边的 serviceName 是方法参数（电视原来的设备名），别改成别的。只改这一处——不要动 AirPlay 相关的注册名字，AirPlay 仍然用原来的设备名。
  5. 打包：菜单 Build → Build App Bundle(s) / APK(s) → Build APK(s)；或在项目目录里用命令行： 
    ./gradlew assembleDebug
（32 位电视：./gradlew assembleDebug -PbuildArm32=true
 64 位电视：./gradlew assembleDebug -PbuildArm64=true）
    产物在 MiracastReceiver/app/build/outputs/apk/ 里，找文件名带 armeabi-v7a（或对应架构）的那个 apk。这是 debug 包，会自动带上可安装的签名，功能与正式版相同。
  6. 先卸载电视上的原版（签名不同，不卸载装不上）： 
    adb -s 192.168.1.30:43733 uninstall com.weekd.miracastreceiver
  7. 装新包： 
    adb -s 192.168.1.30:43733 install -r 你的新包文件名.apk
  8. 在电视上打开应用，确认「显示在其他应用上层」等权限仍在（卸载重装后可能需要重新给一次）。

怎么验证修好了：

dns-sd -B _airplay._tcp local.
dns-sd -B _miracast-receiver._tcp local.

应看到：AirPlay 服务的名字是电视设备名（解析过去是 7000 端口），而自定义服务的名字是「设备名 + MR」（8080 端口）。之后在 iPhone 的「屏幕镜像」里选不带 MR 的那个名字——带 MR 的是自定义服务，不是 AirPlay。

以后官方发布新版、想换回官方版：先卸载再装（同样是签名问题）。想留在自己打的包上也完全可以。

十、收尾与安全

  • 安装完成后，电脑上执行收尾（断开连接、停掉 ADB 后台）： 
    adb disconnect
adb kill-server
  • 不再需要用无线调试时，在电视上把「无线调试」关掉；开发者选项里的「已配对设备」可以随时「忘记」这台电脑。
  • 需要维护时再把无线调试打开即可，不用长期开着。
  • 不要在任何路由器上把 ADB 端口映射到公网；不要在公共网络下开启无线调试。
  • 请只调试自己拥有或有权管理的设备。

关键信息：
- 软件：MiracastReceiver（GitHub: weekdayjast/MiracastReceiver），从 Releases 下载 v1.2.5，包名 com.weekd.miracastreceiver

- 流程：电脑装 ADB → 电视开发者选项打开「无线调试」→ adb pair（用配对端口+配对码）→ adb connect（用连接端口）→ getprop 核对型号 → adb install 安装 → 电视上打开应用并授予「附近设备/位置」「显示在其他应用上层」权限 → 验证：DLNA 用 curl http://电视IP:8080/device.xml（应包含 MediaRenderer）；AirPlay 用 dns-sd -B _airplay._tcp local.（应看到电视名）

- 已知问题：少数索尼机型 AirPlay 列表为空（应用内部两个 mDNS 服务同名冲突），如遇到请参考教程「专治 AirPlay」一节的方案
